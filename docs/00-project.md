# Паспорт проекта

## 1. Общие сведения

| Поле | Значение |
|---|---|
| Название | Journalist Assistant («the-web») |
| Происхождение | Собственный проект |

| Назначение | Веб-приложение для журналистских расследований: доска со связями между карточками, хронология событий, хранилище доказательств, заметки, поиск и лента новостей по теме расследования |

## 2. Пользователи и роли

| Роль | Возможности |
|---|---|
| user (журналист) | Создаёт и ведёт только свои расследования, загружает и скачивает свои файлы, ведёт хронологию и заметки |
| manager (редактор) | Видит и редактирует чужие расследования, управляет обычными пользователями |
| admin | Все права, назначение ролей, удаление пользователей |
| Внешняя система | NewsAPI.org: подбор новостей по ключевым словам |

## 3. Три основные функции

1. Доска расследования: карточки, тексты, изображения и связи между ними с сохранением состояния.
2. Хранилище доказательств: загрузка файлов в MinIO, метаданные, теги, уровень доверия, фильтрация.
3. Хронология событий расследования с прикреплёнными файлами.

## 4. Сущности предметной области

User (с ролями), Investigation, File, TimelineEvent, Note. Всего пять, что укладывается в требование курса (3–5).

## 6. Структура проекта

```
the-web/
├── backend/
│   ├── Dockerfile, requirements.txt, pytest.ini, .env
│   └── app/
│       ├── main.py            точка входа FastAPI, CORS, /health, init_db
│       ├── config.py          настройки (S3, БД, JWT) из переменных окружения
│       ├── database.py        подключение SQLAlchemy
│       ├── create_admin.py    создание admin / manager / user при старте
│       ├── file_storage.py    работа с файлами
│       ├── api/               роутеры: auth, user, investigation, timeline,
│       │                      note, files, search, board, external, seo, token
│       ├── models/models.py   модели БД
│       ├── schemas/           Pydantic-схемы
│       ├── dependencies/      аутентификация и проверка ролей и прав
│       ├── services/          s3.py (MinIO), news_api.py (NewsAPI)
│       ├── utils/             jwt.py, seo.py
│       └── tests/             unit, integration, e2e
├── frontend/
│   ├── Dockerfile, nginx.conf, package.json, package-lock.json
│   └── src/
│       ├── App.tsx            маршруты
│       ├── pages/             Auth, BoardSelection, InvestigationBoard,
│       │                      Timeline, EvidenceStorage, AdminPanel
│       ├── components/        карточки, формы, модальные окна, Navbar и др.
│       ├── context/           AuthContext
│       └── services/          клиент API
├── docker-compose.yaml        minio, backend, frontend, nginx
├── nginx.conf                 прокси: /api/ → backend, / → frontend
├── .env.example
└── .github/workflows/ci-cd.yml
```

**Точки входа:** backend: `backend/app/main.py` (`uvicorn main:app`), frontend: `frontend/src/index.tsx`.

**Внешние зависимости и сервисы:** MinIO (S3-хранилище файлов, порты 9000/9001), NewsAPI.org (внешний HTTP API, нужен ключ).

**Хранение данных:** SQLite (`sqlite:///./test.db` в Docker, `journal.db` локально), файлы лежат в MinIO. Доска хранится в поле JSON `Investigation.board_data`.

**Конфигурация:** переменные окружения и `.env` (`DATABASE_URL`, `S3_*`, `SECRET_KEY`, `NEWS_API_KEY`, `MINIO_ROOT_USER/PASSWORD`). Шаблон лежит в `.env.example`, но он неполный (нет `NEWS_API_KEY`, `DATABASE_URL`).

**Порты после `docker compose up`:** 80 (nginx), 3000 (frontend), 8000 (API, Swagger на `/docs`), 9001 (консоль MinIO).

## 9. Первые наблюдения о проблемах (→ issues)

1. **bug / безопасность:** ключ NewsAPI закоммичен в `backend/.env`. Нужно отозвать ключ, удалить файл из индекса и добавить в `.gitignore`.
2. **bug / безопасность:** пароли хранятся как SHA-256 без соли (`User.get_sha256_hash`), есть поддержка пароля в открытом виде, а также отладочные эндпоинты `/auth/debug-user/{username}`, `/auth/test-login`, `/auth/simple-login`, `/auth/users/{id}/make-admin`.
3. **bug:** учётные записи admin/manager/user с известными паролями создаются при каждом старте, а `create_admin.py` при перезапуске сбрасывает пароль и роль admin.
4. **bug:** `SECRET_KEY` по умолчанию генерируется заново при каждом запуске (`secrets.token_urlsafe`), поэтому токены перестают действовать после перезапуска. В Docker Compose `SECRET_KEY` читается из окружения, но в `.env.example` её нужно задавать явно.
5. **bug:** `docker-compose.yaml` удаляет БД при старте (`rm -f test.db`), то есть данные не сохраняются между перезапусками.
6. **question:** Dockerfile ставит зависимости без версий и не использует `requirements.txt`; сам файл в UTF-16.
7. **question:** `pytest.ini` не соответствует расположению тестов, а CI не запускает тесты.
8. **question:** в `models.py` дублирующиеся поля пароля (`password` и `password_hash`) и таблицы `Role`/`user_roles`, которые не используются (роли хранятся JSON-массивом).
9. **question:** нет LICENSE, README, CHANGELOG, .gitignore.
