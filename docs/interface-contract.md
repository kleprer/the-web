# Контракт программного интерфейса

## 1. Выбор интерфейса

### Операция и назначение

Для описания выбрана операция создания расследования в приложении Journalist Assistant — HTTP-запрос `POST /investigations/`.

Операция вызывается веб-клиентом от имени авторизованного пользователя при подтверждении формы создания расследования. Она сохраняет новое расследование с названием и описанием, связывает его с текущим пользователем и создаёт начальное состояние пустой доски. Полученные данные веб-клиент использует для открытия доски созданного расследования.

### Связь с пользовательским сценарием и требованием

| Обозначение | Содержание |
|---|---|
| US-2 — «Создание расследования» | Журналист входит в систему, открывает форму создания на странице выбора расследования, вводит название и описание и подтверждает создание. Затем переходит на доску нового расследования. |
| FR-2 | Журналист может создать расследование с названием и описанием. |

Сценарий и требование приведены в [описании требований проекта](01-requirements.md). Выбранная операция реализует серверный шаг сценария US-2 — создание и сохранение расследования.

### Реализация операции

Операция реализована в функции `create_investigation` файла [backend/app/api/investigation.py](../backend/app/api/investigation.py). HTTP-маршрут определяется префиксом `/investigations` и декоратором `@router.post("/")`.

Связанные части реализации:

- [backend/app/schemas/investigation.py](../backend/app/schemas/investigation.py) — модели `InvestigationCreate` и `InvestigationResponse`, описывающие данные запроса и результата.
- [frontend/src/services/api.tsx](../frontend/src/services/api.tsx) — метод `createInvestigation`, вызывающий серверную операцию.
- [frontend/src/pages/BoardSelection.tsx](../frontend/src/pages/BoardSelection.tsx) — создание расследования через пользовательский интерфейс.

В текущей версии реализованы серверная операция, сохранение расследования в базе данных и её вызов из веб-клиента.

## 2. Описание контракта

### Кто и как вызывает

Операцию вызывает веб-клиент (метод `createInvestigation` в `frontend/src/services/api.tsx`) от имени вошедшего в систему журналиста. Для проверки её можно вызвать вручную: через `curl` или Swagger UI на `http://localhost:8000/docs`.

| Параметр | Значение |
|---|---|
| Метод и путь | `POST /investigations/` |
| Адрес сервера | `http://localhost:8000` (backend, запущенный через `docker compose up`) |
| Заголовок `Authorization` | `Bearer <access_token>` — токен доступа, полученный при входе |
| Заголовок `Content-Type` | `application/json` |
| Тело запроса | JSON-объект с полями из таблицы ниже |

**Условие вызова:** пользователь вошёл в систему и передал действующий токен доступа.

### Входные данные

| Поле | Тип | Обязательное | Допустимые значения |
|---|---|---|---|
| `title` | строка | да | Название расследования. Любая строка. |
| `description` | строка или `null` | нет | Описание расследования. Если поле не передано или равно `null`, сохраняется пустая строка. |

Идентификатор пользователя в теле не передаётся: сервер берёт его из токена. Лишние поля в теле запроса игнорируются.

### Результат успешного вызова

Код ответа `200 OK`. Тело ответа — JSON-объект созданного расследования:

| Поле | Тип | Значение |
|---|---|---|
| `id` | целое число | Идентификатор нового расследования. |
| `title` | строка | Переданное название. |
| `description` | строка | Переданное описание или пустая строка `""`. |
| `user_id` | целое число | Идентификатор пользователя, которому принадлежит токен. |
| `created_at` | строка | Дата и время создания в формате ISO 8601. |
| `updated_at` | строка | Дата и время последнего изменения в формате ISO 8601. |
| `is_archived` | логическое | Всегда `false`: новое расследование не в архиве. |
| `board_data` | объект | Пустая доска: `{"cards": [], "texts": [], "images": [], "connections": []}`. |

### Поведение при ошибке

Характерная ошибка — в теле запроса нет обязательного поля `title`. Расследование не создаётся, сервер отвечает кодом `422 Unprocessable Entity`. Тело ответа — JSON, где `detail` — список ошибок проверки данных. Эту ошибку можно распознать по записи с `"type": "missing"` и `"loc": ["body", "title"]`.
